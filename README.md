# Community Health Intelligence

เว็บไซต์บันทึกและจัดการข้อมูลชุมชน 7 เครื่องมือ พร้อมแบบสำรวจ 2 ชุด ใช้ Google Apps Script เป็น API และ Google Sheets เป็นที่เก็บข้อมูล

## ฟีเจอร์แผนที่และความสัมพันธ์

- แผนที่: เริ่มต้นซูมบริเวณตำบลเก่างิ้ว อำเภอพล จังหวัดขอนแก่น กด **ปักหมุดจากแผนที่** แล้วคลิกตำแหน่งครัวเรือนเพื่อเติมพิกัดในแบบฟอร์ม สัญลักษณ์ `*` แทนเบาหวาน และมีสัญลักษณ์เฉพาะสำหรับความดันโลหิตสูง โรคหัวใจ โรคไต และมะเร็ง บันทึกครัวเรือนได้หลายรายการต่อเนื่องด้วยปุ่ม **บันทึกและเพิ่มครัวเรือนต่อ** โดยระบบไม่จำกัดจำนวนรายการ
- รายการครัวเรือนในแผนที่ใช้รหัสครัวเรือนไม่ซ้ำกัน หากกรอกรหัสที่มีอยู่แล้ว ระบบจะแจ้งเตือนและไม่บันทึกรายการซ้ำ ทั้งในหน้าเว็บและ API
- ชีตของทุกเครื่องมือแสดงรหัสรายการเป็นเลขลำดับ 1, 2, 3... แยกตามชีต และจัดลำดับใหม่เมื่อมีการลบรายการ โดยยังเก็บรหัสภายในสำหรับเชื่อมโยงการแก้ไขและลบข้อมูลไว้ในคอลัมน์ที่ซ่อน หลังอัปเดต Apps Script ให้รัน `setupReadableSheets()` หนึ่งครั้งเพื่อจัดรูปแบบและเรียงเลขรายการย้อนหลังในทุกชีต
- แบบสำรวจข้อมูลพื้นฐาน: บันทึกรหัสบ้าน ชื่อครอบครัว และเลขประจำตัวหัวหน้าครอบครัว พร้อมเพิ่มสมาชิกได้หลายคนในครัวเรือนเดียว ครอบคลุมข้อมูลบัตรประชาชน ชื่อ วันเกิด เพศ อายุ สถานภาพสมรส อาชีพ สถานะในบ้าน การศึกษา การวางแผนครอบครัว สิทธิรักษาพยาบาล โรค/ความพิการ และการย้ายเข้า/ออก แต่ละรายการครัวเรือนจัดเก็บในชีต `survey`
- แบบสำรวจข้อมูลสุขภาพครัวเรือนและรายบุคคล (ข้อ 9): กรอกเป็น 5 หน้าต่อเนื่อง ได้แก่ ข้อมูลครัวเรือน, สมาชิกในครัวเรือน, สิ่งแวดล้อม/สุขาภิบาล/อาหาร, สุขภาพแม่และเด็ก และการเข้าถึงบริการสุขภาพ/ข้อเสนอแนะ ย้อนกลับหรือข้ามไปหน้าที่ต้องการได้โดยข้อมูลที่กรอกยังอยู่ เมื่อบันทึกข้อมูลทุกหน้าจะจัดเก็บเป็นรายการเดียวในชีต `healthSurvey` พร้อมคอลัมน์แยกที่อ่านและกรองได้; ใช้รหัสแทนชื่อสมาชิกและเก็บข้อมูลเท่าที่จำเป็น กด **พิมพ์** ในรายการที่บันทึกแล้วเพื่อพิมพ์ข้อมูลครัวเรือนนั้นเป็นเอกสาร A4/บันทึกเป็น PDF
- ทุกเครื่องมือหน้า 1–9 มีปุ่ม **พิมพ์แบบสำรวจ** สำหรับดึงข้อมูลล่าสุดจาก Google Sheets แล้วจัดทำเอกสาร A4 จากรายการข้อมูลในหน้านั้น รวมข้อมูลสมาชิกของแบบสำรวจด้วย ต้องเข้าสู่ระบบก่อนพิมพ์ข้อมูล แบบสำรวจสุขภาพพิมพ์รายการครัวเรือนจากปุ่ม **พิมพ์แบบสำรวจ** ในแต่ละรายการ
- ทุกแผ่นงานมีคอลัมน์แยกตามข้อมูลของเครื่องมือนั้นเพื่อค้นหาและกรองได้ง่าย ส่วนข้อมูล JSON ดิบยังเก็บไว้ในคอลัมน์ที่ซ่อนไว้เพื่อให้ API เดิมทำงานต่อได้ แบบสำรวจจะแยกข้อมูลสมาชิกเป็นคอลัมน์ตามลำดับสมาชิก
- ปฏิทินชุมชนแสดงสรุปกิจกรรมเป็นตารางแยกตาม 12 เดือน พร้อมตารางรายละเอียดกิจกรรมที่ใช้แก้ไขและลบรายการได้ กิจกรรมที่ระบุเป็นฤดูกาลหรือไม่ระบุเดือนจะแสดงในกลุ่มช่วงเวลาอื่น
- แผนที่เริ่มที่ระดับซูม 25 ขยายเต็มหน้าจอได้จากปุ่ม **ขยายแผนที่** และซูมได้สูงสุดระดับ 32 (ภาพถ่ายดาวเทียมต้นทางอาจมีรายละเอียดสูงสุดที่ระดับ 19 การซูมต่อจากนั้นเป็นการขยายภาพและอาจไม่คมชัดขึ้น)
- ผังเครือญาติ: เพิ่มครัวเรือนจากหน้าผังได้ต่อเนื่องด้วย **บันทึกและเพิ่มครัวเรือนต่อ** แล้วเลือกครัวเรือนก่อนเพิ่มสมาชิก ผังเลือกดูแยกตามครัวเรือนได้ สมาชิกเดิมที่ยังไม่ผูกครัวเรือนจะแสดงในตัวเลือกแยกต่างหาก เลือกคู่สมรสและบิดา/มารดาจากสมาชิกที่มีอยู่เพื่อเชื่อมเส้นความสัมพันธ์ พร้อมแสดงพี่น้องเมื่อระบุพ่อแม่ร่วมกัน และเลือก **บุคคลหลัก** เพื่อแสดงสัญลักษณ์เพศแบบทึบ
- โครงสร้างองค์กรชุมชน: เลือกหัวหน้าหรือองค์กรต้นสังกัดในช่อง **ขึ้นตรงกับ / หัวหน้า / องค์กรแม่** เพื่อแสดง mapping ความสัมพันธ์จากบนลงล่าง ตารางรายการเดิมยังคงอยู่ และป้องกันการเลือกผู้ใต้บังคับบัญชาเป็นหัวหน้าเพื่อหลีกเลี่ยงวงจร
- ประวัติบุคคลสำคัญ: Timeline เรียงตามปีเกิดและปีของเหตุการณ์ ใช้รูปแบบ `ปี | เหตุการณ์ | รายละเอียด` หนึ่งเหตุการณ์ต่อบรรทัด รองรับการเรียงปี พ.ศ. และ ค.ศ.

## เผยแพร่เว็บไซต์ผ่าน GitHub Pages

GitHub Pages ใช้โฮสต์หน้าเว็บ ส่วน Google Apps Script ยังคงเป็น API สำหรับอ่านและบันทึกข้อมูลใน Google Sheets โดยหน้าเว็บเรียก API ผ่าน URL `/exec` ที่กำหนดใน `index.html`

1. ตรวจว่า URL `/exec` ใน `index.html` เป็น Apps Script API deployment ที่ใช้งานได้ และทดสอบการเข้าสู่ระบบกับการอ่านข้อมูลก่อนเผยแพร่
2. Push โค้ดไปยัง branch `main` หรือเปิด **Actions → Deploy static site to GitHub Pages → Run workflow** เพื่อเริ่มเผยแพร่
3. หาก GitHub ขอให้ตั้งค่า Pages ให้เปิด repository **Settings → Pages** แล้วเลือก **GitHub Actions** เป็นแหล่งเผยแพร่
4. รอ workflow **Deploy static site to GitHub Pages** สำเร็จ แล้วเปิด URL ที่แสดงใน job สภาพแวดล้อม `github-pages`
5. ข้อมูลยังจัดเก็บใน Google Sheets ผ่าน Apps Script; ห้ามใส่ข้อมูลสุขภาพ ข้อมูลส่วนบุคคล รหัสผ่าน หรือ token ลงใน repository และจำกัดสิทธิ์ API/ชีตตามนโยบายของหน่วยงาน

## ตั้งค่า Apps Script API และรหัสผู้ดูแล

1. ใช้ Apps Script project ที่เชื่อมกับ `SHEET_ID` เดิม หากระบบยังใช้รหัสผ่านเริ่มต้น ให้รัน `changeAdminPassword()` ก่อนเปิดใช้งานและเก็บรหัสผ่านใหม่จาก execution log ในที่ปลอดภัย
2. เผยแพร่ Apps Script เป็น Web app เพื่อให้หน้า GitHub Pages เรียก API ได้ โดยกำหนดสิทธิ์ผู้เข้าถึงให้เหมาะสมกับนโยบายข้อมูล
3. เข้าสู่ระบบด้วยชื่อผู้ใช้ `admin` และรหัสผ่านที่ตั้งไว้ หากเป็น Apps Script project ใหม่ ให้กำหนด `SHEET_ID` ก่อนรัน `setupSystem()` และเก็บรหัสผ่านเริ่มต้นจาก execution log

ข้อมูลสุขภาพ เลขประจำตัวประชาชน และตำแหน่งครัวเรือนเป็นข้อมูลอ่อนไหว ควรเก็บเท่าที่จำเป็น แจ้งวัตถุประสงค์และขอความยินยอม จำกัดผู้มีสิทธิ์เข้าถึง และปฏิบัติตามนโยบายคุ้มครองข้อมูลของหน่วยงาน
